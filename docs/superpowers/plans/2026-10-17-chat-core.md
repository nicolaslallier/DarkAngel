# Core Chat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Claude-style `/chat` page where any signed-in user chats privately with the
exo models behind LiteLLM, with streamed answers and thinking, a model picker that
shows loaded / not loaded, and replies that keep running when the user navigates away.

**Architecture:** FastAPI stores conversations and messages in Postgres (owner-scoped
by `sub`). Each reply is an `asyncio.Task` in an in-process registry (`chat/runs.py`)
that streams from LiteLLM through an `httpx.AsyncClient`, buffers the reply, saves
it to Postgres about every 2 s, and fans SSE events out to any number of subscribers.
The Vue SPA reads those events with `fetch` + `ReadableStream` and renders markdown
through DOMPurify.

**Tech Stack:** FastAPI, SQLAlchemy 2 + Alembic, httpx (async), Vue 3 + Pinia,
`marked`, `dompurify`, `highlight.js`, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-17-chat-core-design.md`

## Global Constraints

- Every `/api/chat/*` route takes `Claims`; every query filters on `claims["sub"]`.
  Another user's id → **404**, never 403.
- `llm_url == ""` → every `/api/chat/*` route returns **503** `Chat is not configured`.
- No `max_tokens` is ever sent to the model.
- `reasoning` is never sent back to the model, and `error` messages are skipped in the context.
- Model text becomes HTML **only** in `frontend/src/markdown.ts`, always through `DOMPurify.sanitize`.
- The LiteLLM key never appears in a response, a log line, an error message or git.
- Upstream errors shown to users are exactly `"<model> is not loaded on the cluster"`
  or `"The model did not answer"`.
- Disconnecting a client never cancels a reply. Only `POST /conversations/{id}/stop` does.
- Backend: ruff, 100 columns; pydantic response models next to their route.
  Frontend: `<script setup lang="ts">`, imports from `@/`, `fetch` only in `api/client.ts`.
- Tests sit in `backend/tests/{unit,integration,regression}/` and `frontend/tests/unit/`;
  the directory decides the marker. Unit tests never touch the network.
- Commit after each task on branch `claude/chat-core`. Never push to `main`.

## Review Focus

1. **The model thinks but gives no answer** (399 of 400 tokens were reasoning in the
   live test): the reply saves as `complete` with `content == ""`, and the UI shows the
   thinking plus a muted "No answer" line, not an empty bubble. → Task 4, Task 9.
2. **An SSE event or a multi-byte character (French accents) split across two network
   chunks**: parsed whole, no `�`. → Task 6.
3. **The reply finishes between opening a conversation and reattaching** (`/stream`
   returns 204): the store refetches the conversation instead of showing a dead
   spinner. → Task 8.
4. **Another user's conversation id on send, stream, stop, regenerate**: 404, and their
   run keeps going. → Task 5.
5. **Model not loaded / LiteLLM cooldown**: the assistant message saves with status
   `error` and the safe text, and Regenerate on that message deletes it and retries.
   → Task 4, Task 5.

### Task 2: LLM client

**Files:**
- Create: `backend/app/chat/__init__.py`, `backend/app/chat/llm.py`
- Test: `backend/tests/unit/test_chat_llm.py`

**Interfaces:**
- Produces:
  - `class LlmError(Exception)`: its `str()` is safe to show.
  - `@dataclass(frozen=True) class ModelInfo: id: str; loaded: bool | None; context_length: int`
  - `Event = tuple[str, ...]`: `("reasoning", str)`, `("content", str)`, `("usage", dict)`, `("progress", int, int)`.
  - `class LlmClient(base_url: str, api_key: str, exo_url: str, timeout: float, transport: httpx.AsyncBaseTransport | None = None)`:
    - `async models() -> list[ModelInfo]`, cached 10 s on the instance.
    - `async stream(model: str, messages: list[dict]) -> AsyncIterator[Event]`
    - `async complete(model: str, messages: list[dict]) -> str` (non-streamed, `<think>…</think>` removed, stripped)
  - `def llm_client() -> LlmClient`: FastAPI dependency. Raises `HTTPException(503, "Chat is not configured")` when `llm_url` is empty, else returns a client cached per process (`lru_cache` on an inner builder).

Behaviour the tests pin:
- `models()`: GET `{llm_url}/v1/models` and `{llm_url}/model/info` with `Authorization: Bearer <key>`, plus GET `{exo_url}/state`. The exo id of a LiteLLM model = `litellm_params.model` without its `openai/` prefix. Loaded ids = every `instances.*.<any key>.shardAssignments.modelId`. `loaded` is `True`/`False` for exo models, `None` when `exo_url` is empty, `/state` fails, or the model's `api_base` is not the exo URL. `context_length` = `max_input_tokens` from `/v1/models`, else exo's `/v1/models` `context_length` for that id, else `32768`.
- `stream()`: POST `{llm_url}/v1/chat/completions` with `{"model", "messages", "stream": true, "stream_options": {"include_usage": true}}` and **no** `max_tokens`. `httpx.Timeout(llm_timeout, connect=5)`. Parses `data:` lines until `[DONE]`; `delta.reasoning_content` → reasoning, `delta.content` → content, a chunk with `usage` → usage; a comment line `: prefill_progress {json}` → `("progress", processed_tokens, total_tokens)`. If the content starts with `<think>`, everything up to `</think>` is yielded as reasoning, even across deltas.
- Errors: a response ≥ 400 whose body contains `No instance found` or `all_deployments_in_cooldown` → `LlmError(f"{model} is not loaded on the cluster")`; any other status, `httpx.HTTPError` or malformed JSON → `LlmError("The model did not answer")`. Full detail goes to `log.warning`, never the key.

### Task 4: Reply registry

**Files:**
- Create: `backend/app/chat/runs.py`
- Test: `backend/tests/unit/test_chat_runs.py`

**Interfaces:**
- Consumes: `LlmClient.stream` / `complete`, `LlmError` (Task 2); `ChatRepository.update_message` / `rename` (Task 1).
- Produces:
  - `class Busy(Exception)`
  - `Store = Callable[[], AbstractContextManager[ChatRepository]]`; the default opens `ChatRepository(session_factory()())`.
  - `class Runs(store: Store = default_store, flush_seconds: float = 2.0, title_timeout: float = 60.0)`:
    - `reserve(conversation_id: UUID) -> None`: raises `Busy` if reserved or running. Synchronous and await-free, so it is atomic on the event loop.
    - `release(conversation_id) -> None`: undoes `reserve` when the route fails before `start`.
    - `start(*, owner_sub, conversation_id, message_id, created_at, llm, model, context: list[dict], title_from: str | None) -> None`: turns the reservation into a running `asyncio.Task`. `title_from` = first user message when this is the first reply, else `None`.
    - `running(owner_sub) -> set[UUID]`: that owner's conversation ids with a live run.
    - `subscribe(owner_sub, conversation_id, *, snapshot: bool) -> AsyncIterator[tuple[str, dict]] | None`: `None` if no run for that owner and conversation. With `snapshot=True` the first event is `("snapshot", {"reasoning", "content"})`. Then live events until the run's last event.
    - `stop(owner_sub, conversation_id) -> bool`: cancels that owner's run. `False` if none.
  - Events: `("progress", {"processed", "total"})`, `("reasoning", {"text"})`, `("content", {"text"})`, `("title", {"title"})`, `("done", {"message": <message dict>})`, `("error", {"message": str})`, the last always followed by `done`. Message dict keys: `id, role, content, reasoning, model, status, error, created_at` (ISO string), the same keys as the route's `MessageOut`.
  - `def sse(event: str, data: dict) -> str` → `f"event: {event}\ndata: {json}\n\n"`.
  - `runs = Runs()` module singleton and `def chat_runs() -> Runs` dependency returning it.

Behaviour the tests pin: deltas accumulate into `content` / `reasoning`. While streaming, `update_message(..., content=, reasoning=)` runs at most every `flush_seconds`. The final save sets `status` (`complete` | `stopped` | `error`), `error`, `prompt_tokens`, `completion_tokens`. Cancellation (from `stop`) saves `stopped` and still publishes `done`. `LlmError` saves `error` with its text and publishes `error` then `done`. After a `complete` first reply, `llm.complete(model, [title prompt])` runs with a `title_timeout` limit. A non-empty answer (first line, quotes stripped, ≤ 80 chars) is saved via `rename` and published as `title` before `done`; any failure is silent. Every repository call runs through `asyncio.to_thread`. A subscriber that stops iterating (client gone) is dropped and the task keeps going.

  - `MessageOut(id, role, content, reasoning, model, status, error, created_at)`, `ConversationSummary(id, title, updated_at, streaming)`, `ConversationOut(id, title, streaming, messages: list[MessageOut])`, `ModelOut(id, loaded, context_length)`.
  - `GET /models` → `list[ModelOut]`.
  - `GET /conversations?q=` → `list[ConversationSummary]`.
  - `POST /conversations` `{title?: str}` → 201 `ConversationOut`.
  - `GET /conversations/{id}` → `ConversationOut`.
  - `PATCH /conversations/{id}` `{title: str (1-200, stripped)}` → `ConversationSummary`.
  - `DELETE /conversations/{id}` → 204. Also stops a running reply.
  - `POST /conversations/{id}/messages` `{content: str (1-100000), model: str, replace_from: UUID | None}` → `text/event-stream`. `{id}` may be the literal `new`.
  - `POST /conversations/{id}/regenerate` `{model: str}` → `text/event-stream`.
  - `GET /conversations/{id}/stream` → `text/event-stream`, or 204 when no run.
  - `POST /conversations/{id}/stop` → 204.
  - Stream responses: header `X-Accel-Buffering: no`. First event of a send or regenerate: `start` `{conversation: {id, title}, user_message: MessageOut | null, assistant_message_id}`, then the run's events.

Flow of the two stream-starting routes (`async def`; repository calls via `starlette.concurrency.run_in_threadpool`):
1. Resolve the conversation (or create it with `fallback_title(content)` for `new`) → 404 if not the caller's.
2. `runs.reserve(id)` → `Busy` → 409 `A reply is already running`.
3. Send: with `replace_from`, it must be a `user` message of this conversation (else 404); update its content and `truncate_after` it. Without it, add the user message. Regenerate: if the last message is `assistant`, delete it; if there is no user message, 409.
4. Add the assistant message with `status="streaming"` and `model`.
5. Look up the model's `context_length` via `llm.models()` (default 32768 if absent), `build_context(...)`, then `runs.start(...)` with `title_from` = the content when the conversation had no messages before step 3.
6. Subscribe (`snapshot=False`) **before any further await**, yield `start`, then the run's events as `sse(...)`.
7. Any exception between 2 and 5 → `runs.release(id)`.

`main.py`: `reset_interrupted()` also calls `ChatRepository(db).stop_streaming()`, in its own `try`/`log.exception` so one sweep failing does not skip the other.
